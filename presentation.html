DEFENSE IN DEPTH

Security and Data Isolation

1
Edge Hardening
Public Cloudflare tunnel exposes webhooks only. Header authentication enforced; root and settings paths return 404.
2
Identity Verification
Resource owner always comes from verified Supabase session cookies, NEVER trusted from request bodies.
3
Data Isolation
Row-Level Security (RLS) on all public tables; owner-scoped security definer RPCs; privileged worker schema stays private.
4
Source Fetch Safety
SSRF-fenced reader: DNS resolved and pinned; private and loopback IP ranges blocked; robots.txt strictly honored.
5
Action Safety Boundaries
Separate, revocable consents for email and calendar; idempotent queue execution ensures actions are never duplicated.

Literal quoted facts

Exact text match check

ACT / ASK / IGNORE
✔ WHAT THE AI MODEL MAY DO
• Extract title, organization, deadline, and eligibility.
• Provide verbatim quotes for every extracted fact.
• Propose matching evidence quoting both listing and profile.
• Parse messy markdown and text; nothing more.
• Seamlessly failover from Groq to Gemini Flash Lite.
✖ WHAT THE MODEL MAY NEVER DO
• Return policy fields or declare eligibility status.
• Call external tools, write to DB, or execute side-effects.
• See student credentials, API keys, or private nonces.
• Invent a deadline: missing facts stay NULL.
• Bypass the quota reservation or budget ceilings.

EXTRACTION PROTOCOL

Grounded Extraction Pipeline

01. Safe Source Read
Public static pages only; DNS pinned, redirects checked, robots.txt honored.
02. Hash & Dedupe
Prepared text hashed before AI call; cached extractions reused per user.
03. Bounded Chunking
Listings over 20k characters split by headings; merged without silent truncation.
04. Schema Extraction
Groq/Gemini JSON-schema output; strictly bounded to 5 items max; no tools.
05. Validate Evidence
Every fact verified with literal quote; dates, timezones, and ranges checked.
FOUR REQUIREMENT CLASSES
1. mandatory_eligibility
Hard constraints (degree, branch, CGPA, graduation year).
2. required_skill
Core technical competencies essential for the role.
3. preferred_skill
Bonus skills; NEVER cause a hard eligibility failure.
4. other_requirement
Benefits, visa rules, or non-technical requirements.
Rule: Unstated criteria are marked NOT_STATED, never failed.

DECISION POLICY

Deterministic Decision Engine

1. Deadline already expired IGNORE
2. A stated mandatory requirement fails IGNORE
3. Eligibility is UNKNOWN (missing student fact) ASK
4. Eligible, but match score is below 40 IGNORE
5. Score and confidence meet active autonomy mode threshold ACT
6. Otherwise (borderline match or confidence) ASK
MATHEMATICAL CONFIDENCE FORMULA
Confidence = min( model_confidence, 0.30 × completeness + 0.30 × verified_evidence + 0.25 × clarity + 0.15 × model_confidence )

Workflow 01: Ingest

WEBHOOK POST (Web & Extension)
1. Webhook POST received from web app or extension.
2. Payload validated against strict Zod intake schema.
3. User session verified directly with Supabase Auth.
4. Atomic raw item created in public.raw_items.
5. Returns confirmed HTTP 201 response with queued ID.
6. Triggers 02 Understand asynchronously.
IMAP (Forwarded Email Alerts)
1. IMAP trigger polls dedicated agent mailbox.
2. Recipient alias token validated before AI parsing.
3. Email body parsed into discrete opportunity items.
4. Owner identity resolved via email_alias_token in DB.
5. Discovered raw text stored with attributed provenance.
6. Enqueued for evaluation in 02 Understand.

DECISION CONTRACT

Workflow 03: Evaluate and Decide

HARD ELIGIBILITY
Deterministic code checks student profile (degree, branch, CGPA, graduation year) against mandatory requirements.

• Mandatory fail → IGNORE
• Mandatory unstated → ASK
DOUBLE-SIDED QUOTES
AI proposes semantic match evidence. Code validates quotes exist on BOTH sides: verbatim quote from job listing AND verbatim quote from student profile.

Zero hallucinated fit claims.
DETERMINISTIC ROUTING
Computes composite score and mathematical confidence.

• ACT: Starts 04 Act
• ASK: Starts 05 Ask & Approve
• IGNORE: Saved with reasons

DEFENSIVE ARCHITECTURE

Built to Fail Safely

🔄 Idempotent Intake
Unique request IDs ensure duplicate or overlapping submissions create exactly one database row.
🔒 Fenced Work Claims
Claim tokens and revisions prevent stale background runs from overwriting current decisions.
👁️ Visible Failures
Quota limits and interrupted states are shown transparently in the UI—never silent success.
✉️ Safe Retries
No blind retries after uncertain socket sends. Calendar events reconcile state before create.
🔑 Redacted Secrets
A shared sanitizer strips API keys and credentials before logging errors to the student activity stream.
🔔 Separate Consents
Email notifications and Google Calendar sync have independent opt-ins. Downloadable .ics links always work.
